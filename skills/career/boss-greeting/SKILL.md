# BOSS直聘个性化招呼语生成器

## When to Use

用户需要为BOSS直聘上的职位生成打招呼语时触发。典型输入：
- 用户提供职位链接或职位描述文本
- 用户说"帮我写个招呼语"、"这个职位怎么打招呼"
- 用户粘贴了一段JD（Job Description）

## User Profile (内置用户画像)

**不要让用户每次重复输入这些信息。** 首次使用时确认一次，后续从记忆中读取。

- 姓名：由用户首次使用时提供
- 经验：26年技术经验
- 核心技术栈：Linux/BSD系统级开发、Claude Code/Codex等AI编程工具、智能体(Agent)搭建
- AI能力：LangChain/RAG/向量数据库检索、Agent架构设计与实现
- 项目经验：独立开发过AI笔记智能体（note-agent）、自动求职智能体
- 全栈能力：前端到后端到基础设施，产品感知强，0-1项目经验丰富
- 求职方向：AI Agent技术岗位 / 技术合伙人
- 偏好：远程优先
- 风格：务实直接，不油腻

## Procedure

### Step 1: 解析输入

从用户输入中提取：
1. **职位名称** — 如"AI Agent工程师"、"技术合伙人"
2. **公司名称** — 如有
3. **JD关键词** — 技术要求、业务方向、团队规模、融资阶段
4. **薪资范围** — 如有
5. **城市** — 如有（远程/onsite）

如果用户只给了链接（没有文本），提示用户粘贴职位描述的关键部分。

### Step 2: 匹配度评估

快速评估用户画像与职位的匹配度（1-10），输出：
- 匹配的核心点（2-3个）
- 潜在差距（0-2个）
- 总体评分

**匹配度低于5分时**，先告知用户"这个职位和你的背景匹配度不高"，询问是否仍需生成招呼语。

### Step 3: 生成招呼语

**核心原则（来自真实HR反馈）：**
1. **禁止空洞模板** — 不写"您好，我对贵公司岗位很感兴趣，请看简历"
2. **关键词复现** — 把JD中的关键技术词在招呼语中原样复现
3. **具体成就前置** — 第一句话就亮出最相关的经验和成果
4. **控制在80-120字** — BOSS直聘招呼语字数上限约150字，但80-120字效果最佳
5. **一条核心信息** — 每条招呼语只突出一个最强的匹配点，不要面面俱到
6. **自然不油腻** — 不用emoji堆砌，不用"热血沸腾"这类假热情

**生成3个版本供选择：**

#### 版本A：经验直击型
结构：`称呼 + 最相关经验 + 与JD的匹配点 + 期望`

示例模板（根据实际JD替换）：
> 您好，我有26年技术经验，近两年专注AI Agent方向，独立搭建过基于LangChain+RAG的智能体产品并上线运营。看到贵司在招AI Agent工程师，我的Agent架构设计和向量检索经验应该能快速上手。方便聊聊吗？

#### 版本B：成果展示型
结构：`称呼 + 具体项目成果 + 技术栈匹配 + 期待`

示例模板：
> 您好，我独立开发过一个AI笔记智能体（LangChain+RAG+向量检索），从0到1完成产品设计和部署。贵司这个AI Agent岗位需要的Agent搭建能力和全栈经验，恰好是我每天都在做的事。期待交流。

#### 版本C：实战亮剑型（用户首选风格）

**该用户的偏好风格：简洁直接，开头立即亮身份（经验年限+特长领域），然后快速衔接近期专注方向。**

结构：`26年Linux/BSD资深工程师，曾参与多个开源社区建设 + 近期专注方向 + 核心工具 + 交付成果 + 期望`

示例模板（根据实际JD替换）：
> 您好，26年Linux/BSD资深工程师，曾参与多个开源社区建设。近一年All in AI Agent。Claude Code、Codex重度使用者，独立交付过完整Agent产品。找AI Agent方向的机会，能带系统级工程能力和Agent实战经验入场。方便聊吗？

**关键格式原则：**
1. 第一句落定身份和资历（年限+领域），不要用"我有X年经验"这种平淡开头
2. 第二句衔接近期专注于什么方向
3. 第三句具体化：用什么工具、做了什么项目
4. 最后一句点明诉求
5. 全篇控制在80-120字，不用多余修饰词

### Step 4: 输出格式

```
## 匹配度：X/10
**匹配点**：...
**差距**：...

### 版本A（经验直击型）
> [招呼语文本]
字数：XX

### 版本B（成果展示型）
> [招呼语文本]
字数：XX

### 版本C（[根据职位类型命名]）
> [招呼语文本]
字数：XX

---
💡 建议：该用户首选版本C（实战亮剑型）。先用A/B/C试探，用户确认偏好后后续默认出版本C。
```

### Step 5: 迭代优化

用户选择一个版本后，支持：
- "缩短到80字以内"
- "更正式一些" / "更口语化"
- "突出XX经验"
- "加入对XX的了解"（如公司业务、融资情况）

## Pitfalls

- **不要生成千篇一律的模板** — 每条招呼语必须针对具体JD定制
- **不要超出BOSS直聘字数限制** — 控制在80-120字
- **不要虚构经历** — 只用用户画像中确认的信息
- **不要用HR一天收到几百条的理由去堆砌信息** — 短而精才是竞争力
- **不要用emoji** — 除非用户明确要求
- **英文职位名保留英文** — 如"AI Agent"不要翻译成"AI智能体"

## Verification

1. 招呼语是否包含JD中的至少2个关键词？
2. 是否在80-120字？
3. 是否与用户画像一致（无虚构）？
4. 是否有3个不同版本供选择？
5. 匹配度评估是否合理？
